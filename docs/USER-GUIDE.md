# 开发环境安装器完整指南

## 使用前准备

1. 使用 `程序/开发环境安装器` 完整目录，保持其中的 `DevEnvironmentInstaller.exe`、`config`、`engine`、`packages`、`component-icons`、`ui-icons`、`contact-images` 和 `platform-promo-v3.png` 在同一个目录中。
2. 关闭正在使用 Node.js、Java、Python、MySQL 或 VS Code 的程序。
3. 如果准备替换已有 MySQL，请先确认当前 root 密码可用。
4. 双击正式发布 EXE 后，Windows 会先显示一次管理员权限确认；接受后，本次启动会话内的安装、替换、SQL 导入和环境修复共用这次授权，不会重复弹窗。拒绝时仍可进入只读检测，但特权操作不可执行。开发模式通过 `dotnet xxx.dll` 启动时不会自动请求 UAC。
5. 首次启动会自动弹出浏览器设备授权窗口；点击“打开平台并登录授权”进入计算机资源共享平台。已登录时确认本机授权即可继续，未登录时先登录或注册再确认。

当前本地构建没有商业代码签名，Windows 可能额外显示 SmartScreen 提示。只应从项目的完整分发目录运行，并先核对 `PACKAGE-SHA256SUMS.txt`；正式公开分发时应由发布方完成 Authenticode 签名。

程序启动后先进行只读检测，不会自动安装或卸载任何内容。

右侧“本地安装路径”用于设置安装器管理的便携环境根目录。点击路径或“应用”前，安装器会创建目录并用临时文件验证可写性；失败时不会保存为有效安装路径。Maven、pnpm、Connector/J 等归档环境会安装到该根目录，MySQL、Node.js、JDK 等厂商 MSI/EXE 若没有可控安装目录则遵循厂商默认位置。检测到安装位置后，组件行的“打开”可直接打开资源管理器。

“环境变量审计”会检查机器级和用户级 Path 以及 `JAVA_HOME`、`MAVEN_HOME`、`MYSQL_CONNECTOR_J_HOME`。如果发现旧版本入口、失效目录或缺少当前工具 Path，可点击“修复”，确认后自动清理并写入当前配置。修复完成后必须新开 CMD / PowerShell 才能看到最新变量。

程序启动不会保存管理员密码、Token、计划任务或服务，也不会读取或保存浏览器密码、Cookie 或平台授权密钥。管理员授权只在当前启动会话有效，退出程序后下次启动仍由 Windows 重新确认。安装器仅保存一次性设备授权申请标识，并在每次启动时向平台复核；未授权时可查看本机状态，但无法执行安装、SQL 导入或环境修复。

界面采用亮色液态透明玻璃风格：半透明圆角面板用于组织安装方式、环境清单、MySQL 设置和日志，窗口本身保持普通 WPF 硬件渲染，不使用整窗透明叠层。点击安装后会打开进度面板，显示总体百分比、当前组件、当前阶段和逐组件进度。每个组件按“安全校验、执行安装程序、刷新环境配置、安装后验证”顺序更新状态，完成后自动重新检测。

## 状态颜色

- **绿色：已安装**。电脑中已检测到相同或更新版本。
- **红色：未安装**。电脑中未检测到该组件。
- **橙色：版本较旧或存在冲突**。建议查看右侧日志或改用自定义安装。
- **灰色：检测中**。

## 授权、联系与帮助

- 点击“打开平台并登录授权”会使用默认浏览器打开计算机资源共享平台。登录或注册成功后，在网站确认当前设备授权，再返回安装器等待自动检测或点击“我已完成，检查状态”。授权申请有效期为 10 分钟，过期或被拒绝时可重新发起。
- “程序开发需求”展示微信、QQ、抖音三种联系方式；“公益赞助”展示支付宝和微信二维码。图片仅用于本地展示，不会自动上传。

## 安装方式

### 全面安装

适合第一次配置开发环境。程序只勾选红色“未安装”组件，已安装的软件不会被修改。

### 全面并替换安装

适合统一软件版本或修复严重损坏的环境。程序会处理全部组件：

- MSI 软件只通过 Windows 注册的产品代码静默卸载。
- EXE 软件必须存在明确的静默卸载命令，否则停止并提示手动处理。
- Visual C++ 运行库使用覆盖修复，不进行短暂且高风险的系统级卸载。
- 便携版只清理安装器管理的 `C:\Program Files\DevEnvironment` 子目录。
- 不删除用户项目、源码、仓库、桌面文件或来源不明的便携软件目录。

替换模式必须在向导页“安装模式选择”下方勾选“我确认替换模式会卸载已识别组件”后才能开始；普通全面安装和自定义安装时该复选框保持禁用，避免误触。安装按钮会在扫描完成后保持可点击，用于显示缺少的授权、协议、风险确认、密码或路径条件，不会绕过这些安全校验。

### 自定义安装

适合只需要部分工具的用户。可逐项勾选，依赖组件会自动加入安装计划。例如选择 pnpm 时会自动加入 Node.js。

## MySQL 设置

- **新的 root 密码**：至少 6 个字符，需输入两次。
- **现有 root 密码**：只在替换并迁移已有数据库时需要。
- **服务名称**：默认 `MySQL84`。如果目标服务名已存在，安装器会自动选择带后缀的备用服务名，不会停止同名旧服务。
- **端口**：默认 `3307`，避免与常见的 MySQL 3306 冲突。如果用户填写的端口在安装前或安装过程中被占用，安装器会从下一个端口开始选择可用端口，并在日志和界面中显示最终端口；现有服务不会被停止。
- **保留并迁移现有数据库**：只要检测到现有 MySQL 且本次操作会更新、替换或重装，安装器会强制开启保护流程。它会先验证旧 root 密码，生成只包含用户数据库的逻辑 SQL、SHA-256 校验记录和数据库/表/行快照；空数据库、表、触发器、存储过程和事件均会进入迁移范围，旧 `mysql` 系统库不会覆盖新实例。备份前后快照不一致时会在变更前中止。
- **允许局域网连接**：默认关闭。开启后仍需自行配置 Windows 防火墙和数据库用户权限。

### SQL 数据导入

在“MySQL 数据导入”面板选择 `.sql` 文件，输入数据库名称，并填写“导入 SQL 使用的 root 密码”。点击“导入 SQL”后，安装器会先验证文件和数据库名，连接当前 MySQL 服务，执行 `CREATE DATABASE IF NOT EXISTS`，再导入整个 SQL 文件。数据库名称只允许字母、数字和下划线，导入密码只保存在当前用户的 DPAPI 临时凭据中。

已有 MySQL 的用户数据库逻辑备份和同名 JSON 校验记录保存在：

```text
C:\ProgramData\DevEnvironmentOfflineInstaller\Backups
```

恢复后的表数、总行数和快照摘要不一致时，安装会失败并保留备份。为保证可回滚，安装器不会自动删除旧服务或旧数据库数据目录；旧实例可能与新实例使用不同的服务名或端口。

## Java 设置

OpenJDK 17 和 25 可以同时安装。默认选择 JDK 25 作为 `JAVA_HOME`；如需兼容仅支持 Java 17 的项目，可在设置中心切换为 JDK 17。设置中心保存的是版本特征号或完整 MSI 版本号，安装器会统一识别为 17 或 25。

## 安装日志

执行日志保存在当前 Windows 用户的本地诊断目录：

```text
%LOCALAPPDATA%\DevEnvironmentInstaller\Logs
```

每次检测、安装、环境修复或 SQL 导入都会生成带时间戳的 `.log` 和 `.events.log` 文件。可在文件资源管理器地址栏输入上述路径打开；如果安装器无法上传错误报告，这些文件仍会保留。密码不会写入安装计划、命令行或日志。界面中的密码通过当前 Windows 用户的 DPAPI 临时加密，安装结束后删除。

## 错误报告上传与查看

发生无法自动恢复的错误时，安装器会先脱敏，再向 `http://47.114.72.23/api/installer/error-reports` 提交摘要和日志。云端报告保存在平台的 `platform_state.installerErrorReports` 状态快照中，不会把密码、令牌或授权信息写入报告。管理员登录平台后可通过 `GET /api/admin/installer/error-reports?pageNo=1&pageSize=20` 查看最近报告；接口返回内容仍为脱敏文本。

## 常见停止原因

- 安装包缺失或 SHA-256 不一致。
- 端口范围无效，或从目标端口开始连续没有可用端口（自动回退也会明确记录失败原因）。
- MySQL 现有密码错误或备份失败。
- 某个旧软件没有安全的静默卸载方式。
- 磁盘空间不足或安全软件阻止安装程序。

出现错误时不要强制删除软件目录。先查看日志，根据提示手动处理对应组件，再重新打开安装器检测。

## 商用发布前检查

发布前请阅读同目录的 `COMMERCIAL-READINESS-REPORT.md`。当前版本已经过只读检测和自动化烟测，但真实管理员安装、卸载、MySQL 备份/替换/恢复以及失败回滚必须在干净 Windows 10/11 x64 环境完成；主程序未签名时不要绕过 SmartScreen 或向商业用户分发。
